# content-hub 功能特性文档

> 本文档从**用户使用功能的角度**梳理 content-hub 的功能，作为后续开发的基线。
> 文档状态：v2 收敛版（重写）。相比 v1 收敛了范围：去掉审核/多角色流转/多版本打包，聚焦「知识库管理 + 工作区稿件生成工作流」。
> 技术实现细节（多 agent 分工、存储模型、数据模型）见 `docs/architecture/`。

## 1. 项目定位

多 agent 架构的**政企内容管理平台**。面向政企单位的普通工作人员和有限的管理员，提供两大能力：

1. **单位内部知识库管理**：管理公/私有的 txt / md 文字资料（类似于带目录的网盘）。
2. **稿件生成工作流**：基于知识库检索到的资料，自动生成政企发布的文字稿件（平台不限定，用户选择目标发布平台），并输出稿件与证据原文的对应关系。

核心价值：让生成的稿件**有据可查、来源可溯**——稿件中的每个文段/数据都能回指到知识库中的原始文字片段。

## 2. 角色与权限

单租户（单个企业/单位）下仅两类角色：

| 角色 | 数量 | 权限 |
|------|------|------|
| **管理员** | 每个租户暂时限制 1 个 | 可创建工作人员账号；可操作**公有知识库**和**自己的私有知识库**；其余功能与工作人员完全相同 |
| **工作人员**（普通用户） | 不限 | 只能操作**自己的私有知识库**；创建/操作自己的工作区 |

### 2.1 公有库 / 私有库的访问边界

- **公有知识库**：仅管理员可操作（上传、建目录、管理文件）。
- **私有知识库**：每个用户各有一个自己的私有库，仅本人可见可操作；管理员也拥有自己的私有库。
- 无论公有还是私有，都是**目录 + 文件**的管理形式。

## 3. 知识库管理

### 3.1 文件类型与内容

- 仅处理**纯文字**：现阶段只支持 **txt** 和 **md**（markdown）两种文件。
- **不含**图片、音视频等非文字内容；知识库处理与稿件撰写工作流均只处理纯文字。

### 3.2 目录与文件

- 结构为**目录 + 文件**的层级管理形式（可创建目录）。
- 底层实际存储使用**阿里云对象存储（OSS）**，文件在物理上是**扁平化的**；目录与文件的层级关系需要在系统内自行维护逻辑映射（此为技术约束，详细见 architecture 文档）。

### 3.3 浏览/预览/下载

- 支持在线预览 / 下载文件。
- 支持按文件名检索文件（用于上传覆盖时的选择等）。

### 3.4 上传与覆盖（版本管理）

- 所有用户（管理员与工作人员）都可在自己有权限的知识库内上传文档。
- 上传时可选择：
  - **新文件**：作为新文档加入知识库。
  - **覆盖已有文件的旧版本**：提供文件搜索 → 选择目标文件 → 作为其新版本覆盖写入。
- **版本语义**：
  - 每个文件存在**不可变唯一标识** `document_id + version_no`（新版本继承同一 `document_id`，`version_no` 递增）。
  - 文件新旧**只影响可见性和可搜索性**：知识库搜索**默认只搜每个文件的最新版本**；旧版本**不在搜索范围内**。
  - 旧版本文件**后台不会删除**，但**界面上当前阶段不提供可见/下载入口**（预留能力，后续可能支持按版本预览，本期不做）。
- **边界（上传/解析失败兜底）**：
  - 若某版本上传失败，或“上传成功但**尚未成功完成解析 + 向量化入库**”，则该版本不视为成功。
  - 此时该文件的**最新版本** = 上一次**成功完成‘上传 + 全部解析步骤 + 向量化’**的版本。
  - 也就是说，只有完整走完“上传 → 解析 → 向量化”链路成功的版本，才会成为搜索可见的最新版本。

## 4. 工作区 与 需求单

### 4.1 工作区

- 一个工作区 = **一个稿件的生成工作流**；**需求单只是工作区的一部分**。
- 一个工作区对应一个需求单、产出一篇稿件。需要多篇稿件则创建多个工作区。
- 工作区**仅创建者本人**可访问、编辑、操作。
- 用户首页展示其工作区列表，可按需求单字段检索（标题、标签等）。

### 4.2 需求单字段

需求单为**表单**创建，必填字段分两类：

**（1）基础字段（创建时自动生成，用户无需手填）**
- 标题
- 标签（可多个）
- 发布平台（可多个，**枚举写死可选**：微信公众号 / 小红书 / 单位网站 / 微博）
- 创建时间（自动）
- 最近更新时间（自动）

> 上述字段用于首页检索已有的工作区。

**（2）任务要求字段（必填，用户填写）**
- **稿件风格**：
  - 基调
  - 感情色彩
  - 目标受众
  - 发文目的
  - 禁忌话术 或 其他约束
  - 发文主体（如 学校 / 医院 / 法院）
- **字数要求**
- **章节要求**（用户使用文字说明）

### 4.3 数据来源指定

- **不需要**用户主动填写“要用什么数据”。
- 系统根据需求单的任务要求，**自行推理需要用到哪些数据**。
- 用户需在需求单**勾选要引用的知识库目录或具体文档**，以**锁死检索范围**（只在这些勾选范围内搜集数据）。

### 4.4 对话辅助修改

- 创建需求单时为**表单填写**。
- 界面**一侧可同时进行对话**，通过 AI 对话对需求单已有字段进行修改：
  - **可通过对话修改**：稿件风格（基调/感情色彩/目标受众/发文目的/禁忌话术或其他约束/发文主体）、章节要求。
  - **只能手动改选**：字数要求、勾选的文档范围。
- 本质上，对话修改最终都**落回表单字段**：人工直接改，或经 AI 对话改。

## 5. 稿件生成工作流

一个工作区内的稿件生成，分阶段一气呵成：

1. **数据搜集阶段**：分析需求单中的用户任务要求 → 在用户勾选的文档范围内，从知识库搜集相关数据。
2. **稿件撰写阶段**：根据需求单要求，结合数据搜集产物，生成符合要求的稿件。

### 5.1 生成方式

- **一次性全稿**：每次生成都是输出一份完整稿件的新版本，**全稿替换**旧稿。
- **一气呵成**：用户发起后，系统自动「搜集 → 撰写」，无中间人工触发节点。

### 5.2 稿件参考来源标注

- 数据搜集的中间产物**不单独设界面节点**展示。
- 但在**稿件展示交互界面**上，需**注明稿件中某文段 / 数据的参考资料来源**（对应到知识库原文）。
- 这部分来源对应关系**随证据清单一同导出**。

### 5.3 稿件的修改方式

- 稿件本身**不允许用户手动改字**。
- 只能通过**编辑需求单**或**AI 对话调整需求单**后，**重新生成**稿件。
- （一期功能，先做简单处理；后续再优化。）

## 6. 导出

- 条件：稿件**生成完成**后即可导出；只能导**自己工作区**的稿件。
- **边界（重建锁导出）**：若用户调整需求单并**触发重新生成**，则在重新生成**期间禁止导出**（旧稿导出锁定），直到新稿生成完成。
- **格式**：以 **Markdown** 为主，输出**单个合并的 md 文件**，内容顺序：
  1. **稿件正文**（在前）；
  2. **证据清单**（末尾拼接）；
  3. 文件内写入**提示**：说明“稿件经人工编辑后证据失效”。

### 6.1 证据清单（稿件 ↔ 原文 对应关系）

- 证据清单体现稿件正文与知识库资料的**匹配 / 对应关系**：每个被引用的稿件段落 / 数据，对应一个知识库的**原文片段**。
- **溯源锚点**：`document_id + version_no`（不可变唯一标识），可见时附带**章节标题**（切片阶段尽量提取，提取不到留空）。
- **原文片段**：必须是知识库的**原始原话**，**不允许任何加工 / 改写**，用户至少可**复制该片段到原文中搜索核对**。
- 证据清单 = 稿件段落 / 数据 ↔ 原始资料原文片段 的对应关系。

## 7. 搜索与可见性规则

- 知识库搜索默认只搜每个文件的**最新版本**。
- 旧版本文件**不可见、不可下载、不在搜索范围内**（但后台保留不删除）。
- 有效“最新版本”的判定：必须完成「上传 → 解析 → 向量化」全链路成功（见 3.4 边界）。
- 稿件工作流的检索范围被需求单勾选的目录/文档**锁死**。

## 8. 明确不做的事项（首版）

- **不做**第三方平台互通发布流程（不自动推送公众号/小红书/微博，发布由用户另做）。
- **不做**审核 / 审批流程，无初审 / 终审 / 打回。
- **不做**图片 / 音视频等非文字内容的处理。
- **不做**旧版本文件的界面临预览（预留，后续再定）。
- 不支持 txt / md 以外格式（不含 PDF / DOCX 等）。

## 9. 待厘清 / 开放点

> 以下为当期文档尚未完全确定或留待技术方案阶段细化的点，不影响功能主链路。

- 需求单勾选“目录”时，是否包含其下子目录的递归范围，还是仅目录直接文件（待确认，倾向递归）。
- 章节提取对 md / txt 的具体做法（md 标题 vs txt 无结构），详细见 architecture。
- “稿件风格”各子项（基调/感情色彩/…）在需求单界面的呈现形式与校验。
- 覆盖上传时对旧版本 `version_no` 的具体递增规则、并发覆盖的冲突处理（进 architecture）。
- 工作区列表首页检索的具体检索维度（标题匹配 / 标签筛选 / 平台筛选）。
- 重新生成期间“禁止导出”的提示文案与交互细节。
